# 長期メモリ監査

Codex と Claude のネイティブな長期メモリを、既存の保存ポリシーを変えずに監査する。監査結果は一時的に会話へ出力し、ファイルやメモリ保存先へ書き込まない。

## 監査手順

1. まず両エージェントの現在のメモリ機構と保存先を調査する。存在しない保存先は空として扱い、独自の保存ファイルを作らない。
2. 内容を次の4分類に分ける。
   - **恒久的に維持**: 長く変わらない好み、関係、方針、ルール
   - **過去の事実だが現在値として古い**: 過去の出来事としては正しいが、現在の前提に使ってはいけないもの
   - **更新が必要**: 年齢、予定、進捗、数値、健康状態、資産、仕事・プロジェクトの現状など、現在値の再確認が必要なもの
   - **削除候補**: 一時的なメモ、重複、目的を失った情報、分類不能で保持価値がないもの
3. 各項目について、保存先・根拠・分類・推奨操作を監査結果として提示する。秘密情報や個人情報の本文を新規ファイルへ複写しない。
4. **承認前は絶対に更新・削除・移動しない。** 「承認待ち」と明記して終了する。
5. ユーザーが変更対象を明示的に承認した場合だけ、承認された項目に限って既存の保存ポリシーに従い整理する。承認されていない項目は変更しない。

## 実行入口

- Claude Code: `/memory-audit` としてこの Skill を呼び出す。
- Codex: `memory-audit` Skill（`.agents/skills` 経由）を呼び出す。

両入口はこの共通仕様を使うが、保存先の検出と変更操作は各エージェントのネイティブ機構に限定する。定期実行は各エージェントのスケジューラや手動呼び出しから入口を起動し、監査だけで自動変更しない。

## 空・分類不能の場合

メモリが空なら「監査対象なし」と出力して終了する。分類不能な項目は削除せず「更新が必要」または「要確認」として提示し、ユーザーの判断を求める。
